###### Abstract

Many real-world tasks require language models (LMs) to reason over complex contexts that exceed their parametric knowledge. This calls for context learning, where LMs directly learn relevant knowledge from the given context. An intuitive solution is inference-time skill augmentation: extracting the corresponding rules and procedures from context into explicit, natural-language skills. However, constructing such skills for context learning scenarios faces two fundamental challenges: the prohibitive cost of manual skill annotation for long, technically dense contexts, and the lack of external feedback for automated skill construction. In this paper, we propose Ctx2Skill, a self-evolving framework that autonomously discovers, refines, and selects context-specific skills without human supervision or external feedback. At its core, a multi-agent self-play loop has a Challenger that generates probing tasks and rubrics, a Reasoner that attempts to solve them guided by an evolving skill set, and a neutral Judge that provides binary feedback. Crucially, both the Challenger and the Reasoner evolve through accumulated natural-language skills: dedicated Proposer and Generator agents analyze failure cases and synthesize them into targeted skill updates for both sides, enabling automated skill discovery and refinement. To prevent adversarial collapse caused by increasingly extreme task generation and over-specialized skill accumulation, we further introduce a Cross-time Replay mechanism that identifies the skill set achieving the best balance across representative cases for the Reasoner side, ensuring robust and generalizable skill evolution. The resulting skills can be plugged into any language model to obtain better context learning capability. Evaluated on four context learning tasks from CL-bench, Ctx2Skill consistently improves solving rates across backbone models, e.g., lifting GPT-4.1 from 11.1\% to 16.5\%, GPT-5.1 from 21.2\% to 25.8\%.

## 1 Introduction

Current language models (LMs) have achieved impressive performance on problems whose relevant knowledge was present during large-scale pre-training[[5](https://arxiv.org/html/2604.27660#bib.bib99 "System card: claude opus 4.6"), [28](https://arxiv.org/html/2604.27660#bib.bib199 "GPT-5 technical report"), [39](https://arxiv.org/html/2604.27660#bib.bib94 "Qwen3. 5: towards native multimodal agents")], such as competition-level mathematical problems [[14](https://arxiv.org/html/2604.27660#bib.bib92 "Omni-MATH: a universal olympiad level mathematic benchmark for large language models")] and competitive programming challenges [[17](https://arxiv.org/html/2604.27660#bib.bib91 "SWE-bench: can language models resolve real-world github issues?")]. However, many real-world tasks require LMs to learn from complex contexts and leverage new knowledge rather than parametric knowledge to reason and solve them effectively [[26](https://arxiv.org/html/2604.27660#bib.bib6 "A survey of context engineering for large language models"), [36](https://arxiv.org/html/2604.27660#bib.bib90 "Teaching large language models to maintain contextual faithfulness via synthetic tasks and reinforcement learning"), [47](https://arxiv.org/html/2604.27660#bib.bib4 "Agentic context engineering: evolving contexts for self-improving language models")]. Previous works refer to this capability as context learning[[12](https://arxiv.org/html/2604.27660#bib.bib450 "CL-Bench: a benchmark for context learning")]. Effective context learning enables models to reason beyond their pre-trained knowledge and solve complex, domain-specific tasks by learning directly from rich contextual information, much as humans do. For example, it allows LMs to rapidly make use of previously unseen product documentation to generate step-by-step operational procedures or troubleshoot issues.

Despite the central role of context learning in solving real-world tasks, it has been largely overlooked in current research [[16](https://arxiv.org/html/2604.27660#bib.bib5 "Context engineering 2.0: the context of context engineering")]. A key obstacle is the diversity of real-world contexts: contextual knowledge can be conveyed through books, experimental data, and search results, among others, making context learning fundamentally difficult. An intuitive paradigm is inference-time skill augmentation [[3](https://arxiv.org/html/2604.27660#bib.bib96 "Introduction to agent skills")], i.e., extracting rules and procedures from _context_ into natural-language _skills_ that encode reusable procedural knowledge for LMs. This approach has proven effective in many agent tasks [[42](https://arxiv.org/html/2604.27660#bib.bib109 "WebXSkill: skill learning for autonomous web agents"), [49](https://arxiv.org/html/2604.27660#bib.bib108 "SkillWeaver: web agents can self-improve by discovering and honing skills"), [37](https://arxiv.org/html/2604.27660#bib.bib58 "A goal without a plan is just a wish: efficient and effective global planner training for long-horizon agent tasks")], e.g., coding agents [[24](https://arxiv.org/html/2604.27660#bib.bib110 "Scaling coding agents via atomic skills")]. However, this paradigm faces two fundamental challenges in context learning scenarios. Specifically, _(1) Prohibitive Cost for Manual Skill Annotation_: Existing agent skill libraries are predominantly constructed through human annotation [[18](https://arxiv.org/html/2604.27660#bib.bib105 "Organizing, orchestrating, and benchmarking agent skills at ecosystem scale"), [20](https://arxiv.org/html/2604.27660#bib.bib107 "SkillNet: create, evaluate, and connect ai skills"), [41](https://arxiv.org/html/2604.27660#bib.bib106 "SkillOrchestra: learning to route agents via skill transfer")]. However, this paradigm breaks down in context learning scenarios, where contexts are long, technically dense, and domain-specific. Curating high-quality skills requires annotators to fully internalize complex, multi-section documents, a process that is both cognitively demanding and economically infeasible, rendering human-curated skill construction impractical at scale. _(2) Lack of External Feedback for Automated Skill Construction_: Unlike verifiable tasks such as coding or mathematical reasoning [[7](https://arxiv.org/html/2604.27660#bib.bib93 "Training verifiers to solve math word problems"), [31](https://arxiv.org/html/2604.27660#bib.bib479 "DeepSeekMath: pushing the limits of mathematical reasoning in open language models")], where skill quality can be assessed via execution feedback or ground-truth comparison, context learning tasks lack automatic feedback to evaluate whether extracted skills faithfully and completely capture context-specific knowledge. Given only the context, there is no external feedback signal to tell whether a generated skill is useful or whether critical knowledge has been omitted. This feedback-free nature renders automated skill construction pipelines inapplicable [[1](https://arxiv.org/html/2604.27660#bib.bib456 "Evoskill: automated skill discovery for multi-agent systems"), [44](https://arxiv.org/html/2604.27660#bib.bib451 "AutoSkill: experience-driven lifelong learning via skill self-evolution"), [46](https://arxiv.org/html/2604.27660#bib.bib463 "MemSkill: learning and evolving memory skills for self-evolving agents")]. Together, these challenges highlight the need for an automated framework that discovers skills from the context without relying on either human annotation or external feedback signals.

In this paper, we propose Ctx2Skill shown in Figure [1](https://arxiv.org/html/2604.27660#S1.F1 "Figure 1 ‣ 1 Introduction ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?"), which is designed to autonomously discover, refine, and select skills directly from complex contexts via skill-optimized self-play, requiring neither human annotation nor external feedback. At the core of Ctx2Skill is a multi-agent self-play loop [[10](https://arxiv.org/html/2604.27660#bib.bib461 "Survey of self-play in reinforcement learning"), [22](https://arxiv.org/html/2604.27660#bib.bib462 "Search self-play: pushing the frontier of agent capability without supervision"), [48](https://arxiv.org/html/2604.27660#bib.bib460 "π-Play: multi-agent self-play via privileged self-distillation without external data"), [21](https://arxiv.org/html/2604.27660#bib.bib459 "SPIRAL: self-play on zero-sum games incentivizes reasoning via multi-agent multi-turn reinforcement learning")] comprising two competing but co-evolving roles: a Challenger agent, which generates a batch of tasks and associated rubrics [[15](https://arxiv.org/html/2604.27660#bib.bib466 "Rubrics as rewards: reinforcement learning beyond verifiable domains")] based on context and its skill set, aiming to probe deep contextual understanding, and a Reasoner agent, which reads the context and attempts to solve these tasks guided by its current skill set. The core idea of Ctx2Skill is that the two agents co-evolve by iteratively updating their respective skill sets rather than model parameters. Specifically, a neutral Judge agent evaluates the Reasoner’s responses against each rubric, producing feedback on whether it passes. Crucially, both the Challenger and Reasoner evolve through accumulated natural-language skills: failed cases are routed to dedicated Proposer and Generator agents on the Reasoner side to diagnose missing contextual knowledge and update skills accordingly, while easily solved cases are routed to the Challenger side to strengthen its task and rubric generation strategies, ensuring sustained adversarial pressure. The updated skills are carried forward into the next iteration, allowing both sides to continuously co-evolve through failure-driven textual feedback without any parameter updates. Furthermore, we identify a key risk in this multi-agent self-play loop, namely adversarial collapse phenomenon: as iterations progress, the Challenger may generate increasingly extreme tasks while the Reasoner’s skills over-specialize to these pathological cases, resulting in redundant skill accumulation that degrades generalization. To address this, we further propose a Cross-time Replay mechanism that selects the skill set that best balances performance across representative cases, ensuring robust and generalizable skill evolution. At inference time, the resulting context-specific Reasoner skills can be plugged into any LM to enhance its context learning capability on arbitrary tasks over the same context, including those unseen during the self-play loop.

We evaluate our Ctx2Skill on four context learning tasks from CL-Bench[[12](https://arxiv.org/html/2604.27660#bib.bib450 "CL-Bench: a benchmark for context learning")], including Domain Knowledge Reasoning, Rule System Application, Procedural Task Execution, and Empirical Discovery & Simulation. Ctx2Skill consistently improves solving rate across all four categories and multiple backbone models: it raises GPT-4.1 [[27](https://arxiv.org/html/2604.27660#bib.bib193 "GPT-4 technical report")] from 11.1\% to 16.5\%, GPT-5.1 [[28](https://arxiv.org/html/2604.27660#bib.bib199 "GPT-5 technical report")] from 21.2\% to 25.8\%, and GPT-5.2 [[28](https://arxiv.org/html/2604.27660#bib.bib199 "GPT-5 technical report")] from 18.2\% to 21.4\%, demonstrating that autonomously discovered context-specific skills provide substantial and generalizable gains.

## 2 Related Work

Context Learning. Current language models excel at tasks whose relevant knowledge was present during pre-training [[9](https://arxiv.org/html/2604.27660#bib.bib87 "DeepSeek-v3 technical report"), [28](https://arxiv.org/html/2604.27660#bib.bib199 "GPT-5 technical report"), [33](https://arxiv.org/html/2604.27660#bib.bib2 "FaithLens: detecting and explaining faithfulness hallucination"), [34](https://arxiv.org/html/2604.27660#bib.bib3 "Aligning large language models to follow instructions and hallucinate less via effective data filtering")]. However, many real-world tasks require models to learn from complex contexts and leverage new knowledge to reason effectively, a capability termed _context learning_[[12](https://arxiv.org/html/2604.27660#bib.bib450 "CL-Bench: a benchmark for context learning")]. This context learning capability is essential in practice: a physician consults newly released clinical guidelines to adjust treatment, an engineer reads documentation to execute procedures, and a researcher induces patterns from experimental data to form hypotheses. However, prior work finds that LMs have yet to master this capability [[12](https://arxiv.org/html/2604.27660#bib.bib450 "CL-Bench: a benchmark for context learning")]. The core difficulty is that contextual knowledge spans diverse formats, from books to experimental datasets, and the relevant rules and procedures are often embedded implicitly, requiring deep comprehension rather than surface-level retrieval. Ctx2Skill directly targets this challenge by autonomously discovering reusable, context-specific skills from the contexts, equipping any LM to better learn from and reason over complex contexts.

Skills for LMs. Skills are natural-language modules that encode reusable procedural knowledge to augment LMs at inference time [[2](https://arxiv.org/html/2604.27660#bib.bib97 "Equipping agents for the real world with agent skills"), [3](https://arxiv.org/html/2604.27660#bib.bib96 "Introduction to agent skills")], and skill augmentation has been widely validated across agent tasks [[32](https://arxiv.org/html/2604.27660#bib.bib137 "SpokenWOZ: a large-scale speech-text benchmark for spoken task-oriented dialogue agents")], e.g., coding [[24](https://arxiv.org/html/2604.27660#bib.bib110 "Scaling coding agents via atomic skills")] and web navigation [[42](https://arxiv.org/html/2604.27660#bib.bib109 "WebXSkill: skill learning for autonomous web agents")]. Early skill libraries are predominantly constructed through human annotation [[18](https://arxiv.org/html/2604.27660#bib.bib105 "Organizing, orchestrating, and benchmarking agent skills at ecosystem scale"), [19](https://arxiv.org/html/2604.27660#bib.bib455 "SkillsBench: benchmarking how well agent skills work across diverse tasks"), [20](https://arxiv.org/html/2604.27660#bib.bib107 "SkillNet: create, evaluate, and connect ai skills"), [41](https://arxiv.org/html/2604.27660#bib.bib106 "SkillOrchestra: learning to route agents via skill transfer")], which is effective but does not scale, especially for context learning scenarios where contexts are long, technically dense, and domain-specific. Recent work has shifted toward automated skill construction. AutoSkill [[44](https://arxiv.org/html/2604.27660#bib.bib451 "AutoSkill: experience-driven lifelong learning via skill self-evolution")] extracts reusable behaviors from interaction traces as lifelong versioned artifacts, and AutoRefine [[30](https://arxiv.org/html/2604.27660#bib.bib465 "AutoRefine: from trajectories to reusable expertise for continual llm agent refinement")] converts agent trajectories into reusable expertise. CoEvoSkills [[45](https://arxiv.org/html/2604.27660#bib.bib464 "CoEvoSkills: self-evolving agent skills via co-evolutionary verification")] generates multi-file skill packages and refines them through generator–verifier co-evolution, while EvoSkill [[1](https://arxiv.org/html/2604.27660#bib.bib456 "Evoskill: automated skill discovery for multi-agent systems")] performs failure-driven refinement into structured skill folders. SkillX [[40](https://arxiv.org/html/2604.27660#bib.bib452 "SkillX: automatically constructing skill knowledge bases for agents")] distills the agent trajectories into a hierarchical skill knowledge base and iteratively refines them through execution feedback. However, these methods rely on external feedback signals [[25](https://arxiv.org/html/2604.27660#bib.bib467 "SkillClaw: let skills evolve collectively with agentic evolver")], such as execution feedback, ground-truth comparison, or task-completion rewards, to evaluate and improve skill quality, which are not available in context learning scenarios where there is no automatic feedback. A separate line of work tries to internalize skills into model parameters. SKILL0 [[23](https://arxiv.org/html/2604.27660#bib.bib454 "SKILL0: in-context agentic reinforcement learning for skill internalization")] uses in-context reinforcement learning (RL) to absorb skills, and SkillRL [[43](https://arxiv.org/html/2604.27660#bib.bib469 "SkillRL: evolving agents via recursive skill-augmented reinforcement learning")] builds a hierarchical skill bank via RL-guided distillation from teacher trajectories. These approaches require parameter access, making them inapplicable to closed-source models, and sacrificing the interpretability of natural-language skill documents. In this paper, we propose Ctx2Skill, a self-evolving framework designed to directly discover and evolve skills from complex contexts alone, which requires no human annotation, no external feedback, and no parameter updates.

## 3 Methodology

### 3.1 Overview

Context learning tasks [[12](https://arxiv.org/html/2604.27660#bib.bib450 "CL-Bench: a benchmark for context learning")] require LMs to leverage contextual knowledge from long, technically dense contexts to reason and solve tasks effectively. An intuitive paradigm for context learning tasks is inference-time skill augmentation, i.e., extracting the corresponding rules and procedures from _context_ into natural-language _skills_. Turning this idea into a working framework, however, faces two difficulties: (1) prohibitive cost for manual skill annotation and (2) lack of external feedback for automated skill construction. In this paper, we introduce Ctx2Skill shown in Figure [2](https://arxiv.org/html/2604.27660#S3.F2 "Figure 2 ‣ 3.2 Problem Formulation ‣ 3 Methodology ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?"), a self-evolving framework that autonomously discovers, refines, and selects context-specific skills without human supervision or external feedback. At its core, a _skill-optimized self-play_ loop (§[3.3](https://arxiv.org/html/2604.27660#S3.SS3 "3.3 Ctx2Skill Framework ‣ 3 Methodology ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?")) co-evolves two competing sides: a Challenger probes the context with tasks and rubrics guided by its own skill set, a Reasoner solves them under its current skill set, and a neutral Judge returns binary verdicts that route each outcome to a side-specific Proposer–Generator pair, which diagnoses the exposed weakness and edits that side’s skills accordingly, so that both sides co-evolve without human annotation or external feedback. Furthermore, a key risk in this self-play framework is _adversarial collapse_: the Challenger may generate increasingly extreme tasks while the Reasoner’s skills over-specialize to these pathological cases, resulting in redundant skill accumulation that degrades generalization. To address this, we further propose a Cross-Time Replay mechanism (§[3.4](https://arxiv.org/html/2604.27660#S3.SS4 "3.4 Cross-Time Replay Mechanism ‣ 3 Methodology ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?")) that selects the skill set that best balances performance across representative cases, ensuring robust and generalizable skill evolution. In this way, Ctx2Skill autonomously constructs context-specific skills that can be plugged into any LM at inference time to enhance context learning capability without parameter updates.

### 3.2 Problem Formulation

A context learning task [[12](https://arxiv.org/html/2604.27660#bib.bib450 "CL-Bench: a benchmark for context learning")] consists of a given context C whose content may lie outside the LM’s pretraining corpus, a set of tasks \mathcal{T}=\{t_{j}\} whose correct answers depend on C, and a set of binary rubrics \mathcal{R}_{j}=\{r_{j,k}\}. Given an answer a_{j} produced by an LM \pi, the task is considered solved only when every rubric passes, we define a solving indicator y_{j}(\pi;C) for task t_{j} as:

y_{j}(\pi;C)=\prod_{k}\mathbb{I}\bigl[r_{j,k}(a_{j})=\mathrm{pass}\bigr],\qquad a_{j}\sim\pi(\cdot\mid C,t_{j}).(1)

Our goal is to enable the LM \pi to solve tasks over a previously unseen context C without any parameter update or external feedback. To this end, we introduce a natural-language _skill set_\mathcal{S}, a short Markdown file pre-pended to the system prompt of the LM at inference time:

a_{j}\sim\pi(\cdot\mid\mathcal{S},C,t_{j}).(2)

During the skills construction of our proposed Ctx2Skill, \mathcal{S} is instantiated as two separate skill sets: \mathcal{S}^{\mathrm{R}} for the Reasoner agent and \mathcal{S}^{\mathrm{C}} for the Challenger agent. At inference time, only the Reasoner’s skill set \mathcal{S}^{\mathrm{R}} is deployed with an LM for context-specific tasks evaluation.

### 3.3 Ctx2Skill Framework

Building a skill set for an unseen context C faces two obstacles: human annotation is costly to read C and write down its contextual knowledge, and no external feedback signal can tell us whether a proposed skill is faithful and useful to C. To address both, Ctx2Skill runs a multi-agent self-play loop that autonomously discovers and refines context-specific skills from context C alone.

The core idea of Ctx2Skill is to co-evolve two skill sets, skill set \mathcal{S}^{\mathrm{R}} for the Reasoner and skill set \mathcal{S}^{\mathrm{C}} for the Challenger, through N iterations of failure-driven textual edits, so that the Reasoner gradually accumulates the contextual knowledge of the context C while the Challenger keeps probing aspects not yet mastered. Five frozen-LM agent roles carry out this self-play loop. At iteration i, given the context C and skill set \mathcal{S}^{\mathrm{C}}_{i-1}, the _Challenger_ produces a batch of tasks with corresponding rubrics; the _Reasoner_, guided by context C and its skills \mathcal{S}^{\mathrm{R}}_{i-1}, attempts each task; the neutral _Judge_ returns per-task binary verdicts and partitions the batch into failed and solved tasks. Each group is then routed to its corresponding side through a _Proposer_–_Generator_ pair: failed cases flow to the _Reasoner_ side, where the Proposer diagnoses which contextual knowledge is missing and the _Generator_ updates \mathcal{S}^{\mathrm{R}} accordingly; solved cases flow to the _Challenger_ side, where the corresponding pair tightens \mathcal{S}^{\mathrm{C}} so that the next iteration sustains adversarial pressure. The updated \mathcal{S}^{\mathrm{R}}_{i} and \mathcal{S}^{\mathrm{C}}_{i} are carried into iteration i{+}1, and no prompt is ever conditioned on the opposing side’s skill set, keeping the two sides strictly adversarial. We now define the five agent roles as follows at the iteration i:

*   •
_Challenger_: Given the context C and its current skill set \mathcal{S}^{\mathrm{C}}_{i-1}, the Challenger produces a batch of M tasks \{t_{m}\}_{m=1}^{M}, each equipped with corresponding rubrics \mathcal{R}_{m}. The rubrics are designed so that a correct answer requires inducing the rules of C rather than paraphrasing surface spans. By conditioning on its skills \mathcal{S}^{\mathrm{C}}_{i-1}, the Challenger adapts its probing strategy across iterations, sustaining adversarial pressure as the Reasoner improves.

*   •
_Reasoner_: Given C, a task t_{m}, and its current skill set \mathcal{S}^{\mathrm{R}}_{i-1}, the Reasoner produces an answer a_{m}. While the raw context C contains all necessary knowledge, it is often long and technically dense; the skill set \mathcal{S}^{\mathrm{R}}_{i-1} distills the most relevant rules and procedures from C into a concise, structured form, allowing the Reasoner to directly apply contextual knowledge that would otherwise need to be extracted from scratch at every task.

*   •
_Judge_: Given a task and rubrics generated from the Challenger, and the generated answer from the Reasoner, the Judge returns a per-rubric binary verdict z_{m,k}=\mathbb{I}[r_{m,k}(a_{m})=\mathrm{pass}] and a solving indicator y_{m}=\prod_{k}z_{m,k}. The Judge is a strict evaluator: the task is considered solved if and only if the answer satisfies all associated rubrics.

*   •
_Proposer (one per side)_: The Judge’s binary verdicts identify _which_ tasks failed or solved, but not _why_. The Proposer therefore collects all routed cases of its side, where each case comprises the task and rubrics from the Challenger, and the Reasoner’s answer, and jointly analyzes them against the current skill set. Rather than diagnosing each case in isolation, the Proposer synthesizes common failure or success patterns across cases into a high-level diagnosis specifying an action (add or merge), the target skill name, a description, and a justification. The _Reasoner Proposer_ is designed to take the failed cases \mathcal{F}_{i} together with \mathcal{S}^{\mathrm{R}}_{i-1}, and diagnose which contextual knowledge is missing or misrepresented by examining both the incorrect answers and the rubrics they violated. On the other hand, the _Challenger Proposer_ takes the easily solved cases \mathcal{P}_{i} together with \mathcal{S}^{\mathrm{C}}_{i-1}, and identifies gaps in the current task and rubric generation strategy by inspecting how the Reasoner solved them with its existing skills.

*   •
_Generator (one per side)_: The Proposer’s output is a high-level diagnosis describing what should change and why, but not the concrete skill content itself. The Generator materializes this diagnosis into an actual skill set. Given the diagnosis and the current skill set, it returns a complete replacement skill set that adds or merges entries while preserving every unrelated entry. The Reasoner Generator incorporates the diagnosed missing contextual knowledge into \mathcal{S}^{\mathrm{R}}_{i-1} to produce the new skill set \mathcal{S}^{\mathrm{R}}_{i}. The Challenger Generator tightens \mathcal{S}^{\mathrm{C}}_{i-1} so that the next iteration probes the Reasoner’s remaining weaknesses, producing skills \mathcal{S}^{\mathrm{C}}_{i}.

To summarize, at iteration i, the Challenger first produces a batch of tasks and rubrics \{(t_{m},\mathcal{R}_{m})\}_{m=1}^{M} based on the context C; the Reasoner attempts to answer each t_{m}; the Judge evaluates every rubric and partitions the batch into failed cases \mathcal{F}_{i}=\{m:y_{m}=0\} and solved cases \mathcal{P}_{i}=\{m:y_{m}=1\} based on the solving indicator y_{m}. Each group is then routed to its corresponding side:

*   •
The Reasoner Proposer jointly analyzes all failed cases \mathcal{F}_{i} against \mathcal{S}^{\mathrm{R}}_{i-1} and synthesizes a high-level diagnosis; the Reasoner Generator then materializes it into \mathcal{S}^{\mathrm{R}}_{i}.

*   •
The Challenger Proposer jointly analyzes all solved cases \mathcal{P}_{i} against \mathcal{S}^{\mathrm{C}}_{i-1} and synthesizes a high-level diagnosis; the Challenger Generator then materializes it into \mathcal{S}^{\mathrm{C}}_{i}.

The updated skill sets \mathcal{S}^{\mathrm{R}}_{i} and \mathcal{S}^{\mathrm{C}}_{i} are carried forward into iteration i{+}1. No prompt is ever conditioned on the opposing side’s skill set, keeping the two sides strictly adversarial.

### 3.4 Cross-Time Replay Mechanism

The framework of Ctx2Skill detailed in §[3.3](https://arxiv.org/html/2604.27660#S3.SS3 "3.3 Ctx2Skill Framework ‣ 3 Methodology ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?") intentionally strengthens the Challenger across iterations through updates to \mathcal{S}^{\mathrm{C}}, sustaining adversarial pressure as the Reasoner improves. However, this design introduces an inherent tension that we term _adversarial collapse_. As iterations progress, the Challenger generates increasingly extreme tasks that concentrate on the Reasoner’s residual weaknesses, gradually deviating from the representative knowledge of the context C. Since the Reasoner’s skill updates are failure-driven, its skills over-specialize to these pathological cases, resulting in redundant skill accumulation that degrades generalization. Moreover, this collapse is undetectable within the loop: each iteration’s Judge only evaluates the Challenger’s newly generated tasks, providing no signal on whether contextual knowledge mastered in earlier iterations has been corrupted by subsequent edits. Returning the last iteration Reasoner’s skills \mathcal{S}^{\mathrm{R}}_{N} unconditionally is therefore unreliable; we instead select the most generalizable skill set among candidates \{\mathcal{S}^{\mathrm{R}}_{1},\dots,\mathcal{S}^{\mathrm{R}}_{N}\}.

To address this, we propose a _cross-time replay_ mechanism that selects the most generalizable skill set from the candidates \{\mathcal{S}^{\mathrm{R}}_{1},\dots,\mathcal{S}^{\mathrm{R}}_{N}\} using representative probes collected during self-play itself. Two small probe sets are curated incrementally without any external supervision: at each iteration i, the failed task with the lowest rubric pass rate is added to the hard probe set \mathcal{Q}^{\mathrm{h}}, and the solved task with the fewest rubrics is added to the easy probe set \mathcal{Q}^{\mathrm{e}}, capturing the hardest failure and the easiest success observed at each iteration. Once the self-play loop terminates, the Reasoner\pi^{\mathrm{R}} re-answers every task in both probe sets under each candidate skill set \mathcal{S}^{\mathrm{R}}_{i}, and the Judge re-evaluates every rubric, yielding the solving indicator y_{q} (i.e., whether all rubrics pass) for each probe task q. We define the Laplace-smoothed [[13](https://arxiv.org/html/2604.27660#bib.bib98 "Laplacian smoothing and delaunay triangulations")] solving rates \rho^{\mathrm{h}}(i) and \rho^{\mathrm{e}}(i) as the proportion of tasks solved in the hard and easy probe sets under the context C and skills \mathcal{S}^{\mathrm{R}}_{i}, respectively:

\rho^{h}(i)=\frac{\sum_{q\in\mathcal{Q}^{\mathrm{h}}}y_{q}(\pi^{\mathrm{R}};C,\mathcal{S}^{\mathrm{R}}_{i})+1}{|\mathcal{Q}^{\mathrm{h}}|+1},\qquad\rho^{e}(i)=\frac{\sum_{q\in\mathcal{Q}^{\mathrm{e}}}y_{q}(\pi^{\mathrm{R}};C,\mathcal{S}^{\mathrm{R}}_{i})+1}{|\mathcal{Q}^{\mathrm{e}}|+1}.(3)

The selected skill set is the one that maximizes the product of these two solving rates:

\mathcal{S}^{\mathrm{R}}_{\star}=\mathcal{S}^{\mathrm{R}}_{i^{\star}},\qquad i^{\star}=\arg\max_{i}\left(\rho^{\mathrm{h}}(i)\cdot\rho^{\mathrm{e}}(i)\right).(4)

The multiplicative form is essential: a skill set that resolves late, idiosyncratic failures at the cost of regressing on easier tasks incurs a penalty on \rho^{\mathrm{e}}(i) and is rejected; conversely, one that solves every easy probe but fails every hard one is rejected through \rho^{\mathrm{h}}(i). Meanwhile, Laplace smoothing keeps the product well-defined when a probe set is empty for a given iteration

At inference time, the final skill set \mathcal{S}^{\mathrm{R}}_{\star} is prepended to the Reasoner’s system prompt for any unseen task t_{u} over context C, and the Reasoner answers conditioned on (\mathcal{S}^{\mathrm{R}}_{\star},C,t_{u}). Since \mathcal{S}^{\mathrm{R}}_{\star} encodes reusable contextual knowledge of C rather than task-specific solutions, it generalizes to arbitrary tasks over the same context. Moreover, \mathcal{S}^{\mathrm{R}}_{\star} is produced once per context and reused across all |\mathcal{T}| unseen tasks, so the Ctx2Skill cost amortizes over |\mathcal{T}| with no additional cost per deployed query.

Context learning is a newly emerging research topic, aiming to require LMs to learn from unseen context and leverage new knowledge beyond what was acquired during pre-training to reason and solve tasks [[12](https://arxiv.org/html/2604.27660#bib.bib450 "CL-Bench: a benchmark for context learning")]. ### 4.2 Results

Table[1](https://arxiv.org/html/2604.27660#S4.T1 "Table 1 ‣ 4.1 Settings ‣ 4 Experiments ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?") presents the main results on CL-bench. Context learning remains challenging for current frontier LMs: even the best-performing model, GPT-5.1, achieves only a 21.1\% overall solving rate. Ctx2Skill consistently improves solving rates across all three backbones, raising GPT-4.1 from 11.1\% to 16.5\% (+5.4\%), GPT-5.1 from 21.1\% to 25.8\% (+4.6\%), and GPT-5.2 from 18.2\% to 21.4\% (+3.2\%), outperforming both Prompting and AutoSkill4Doc by a large margin across all four categories. The gains are especially pronounced on Procedural Task Execution and Empirical Discovery & Simulation, which demand deeper procedural and inductive reasoning over the context. In contrast, the two baselines provide only modest improvements and occasionally degrade individual categories (e.g., Prompting decreases Rule System Application on GPT-4.1 by 2.5\%), suggesting that single-pass skill extraction is insufficient for complex contextual knowledge. Notably, GPT-4.1 with Ctx2Skill skills (16.5\%) surpasses stronger frontier models without skills, e.g., Gemini 3 Pro (15.8\%), demonstrating that context-specific skills can bridge substantial capability gaps. Beyond solving rate, we assess the intrinsic quality of generated skills using GPT-4.1 as a judge across five dimensions (Table[2](https://arxiv.org/html/2604.27660#S4.T2 "Table 2 ‣ 4.1 Settings ‣ 4 Experiments ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?")). These results indicate that the iterative self-play loop produces skills that not only improve downstream reasoning but also present contextual knowledge in a well-structured, human-readable form amenable to inspection, editing, and reuse.

### 4.3 Analysis

Ablation Study. We ablate each component of Ctx2Skill on both the GPT-4.1 and GPT-5.1 (Table[3](https://arxiv.org/html/2604.27660#S4.T3 "Table 3 ‣ 4.2 Results ‣ 4 Experiments ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?"), Ablation Study block). Removing Challenger skills evolving causes the largest drop, confirming that sustained adversarial pressure is essential for the Reasoner to discover contextual knowledge progressively. The Cross-Time Replay mechanism is the second most impactful: without it, the last-iteration skills suffer from adversarial collapse. Within Cross-Time Replay, the hard probe set contributes more than the easy probe set, and removing Laplace smoothing also degrades performance. Merging the Proposer and Generator into a single agent yields a modest but consistent decline, supporting the decoupling of diagnosis from skill materialization. We also examine the impact across all sub-categories of CL-bench on GPT-4.1 (Figure[4](https://arxiv.org/html/2604.27660#S4.F4 "Figure 4 ‣ 4.3 Analysis ‣ 4 Experiments ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?")). Ctx2Skill improves solving rates on the vast majority of sub-categories, with especially large gains on workflow orchestration (+11.8\%).

Effect of Cross-Time Replay Mechanism. We compare Cross-Time Replay against using a fixed iteration’s skills (Table[3](https://arxiv.org/html/2604.27660#S4.T3 "Table 3 ‣ 4.2 Results ‣ 4 Experiments ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?"), Effect of Cross-Time Replay block). On GPT-4.1, fixed-iteration performance monotonically decreases from Iter-1 (15.9\%) to Iter-5 (14.7\%), confirming that later iterations suffer from adversarial collapse phenomenon. Cross-Time Replay (16.5\%) outperforms every fixed iteration, including the best one (Iter-1), by +0.6\%, by adaptively selecting the most balanced skill set per context rather than committing to a single iteration across all contexts. Skill Transferability Testing. We investigate whether skills generated by one backbone can benefit a different one (Table[3](https://arxiv.org/html/2604.27660#S4.T3 "Table 3 ‣ 4.2 Results ‣ 4 Experiments ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?"), Skill Transferability Testing block). GPT-5.1-generated skills applied to GPT-4.1 yield 16.1\%, nearly matching GPT-4.1’s own skills; conversely, GPT-4.1-generated skills applied to GPT-5.1 yield 23.1\%, a +2.0\% gain but notably below the +4.6\% from GPT-5.1’s own skills. This asymmetry shows that stronger models produce skills that transfer well to weaker models, whereas weaker models lack the capacity to discover knowledge that stronger models can exploit.

## 5 Conclusion

We presented Ctx2Skill, a self-evolving framework that autonomously discovers, refines, and selects context-specific skills from complex contexts without human annotation or external feedback. Through a skill-optimized self-play loop, a Challenger and a Reasoner co-evolve their skill sets via failure-driven textual edits, while a Cross-Time Replay mechanism prevents adversarial collapse by selecting the most generalizable skill set across iterations. Experiments on CL-bench demonstrate that Ctx2Skill consistently and substantially improves context learning performance across multiple backbone models and task categories, and that the resulting skills are transferable across models. We hope Ctx2Skill provides a practical and scalable paradigm for equipping language models with the ability to learn skillfully from complex, previously unseen contexts.

## Appendix B Implementation Details

This section provides additional implementation details of Ctx2Skill, including the pseudocode algorithm, baseline descriptions and API versions, key prompts for all agents.

Baselines and API Versions. We compare Ctx2Skill with two baselines. (1) Prompting directly prompts the LM to read the context C and generate a skill set in a single pass; the resulting skills are then pre-pended to LMs during inference. (2) AutoSkill4Doc 1 1 1[https://github.com/ECNU-ICALK/AutoSkill/tree/main/AutoSkill4Doc](https://github.com/ECNU-ICALK/AutoSkill/tree/main/AutoSkill4Doc) is a variant of AutoSkill[[44](https://arxiv.org/html/2604.27660#bib.bib451 "AutoSkill: experience-driven lifelong learning via skill self-evolution")] designed for document-level contexts: it partitions the context C into different windows, identifies the independent skills within each window, and recombines skills across windows to produce a skill set. All experiments use fixed model snapshots to ensure reproducibility. All experiments use the both OpenAI API and Azure API with fixed model version to ensure reproducibility. For the GPT-4.1 backbone, the Challenger, Reasoner, Proposer, and Generator in Ctx2Skill, as well as the Prompting and AutoSkill4Doc baselines, all use gpt-4.1-2025-04-14. For the GPT-5.1 backbone, these agents and baselines use gpt-5.1-2025-11-13. For the GPT-5.2 backbone, these agents and baselines use gpt-5.2-2025-12-11. The Judge uses gpt-5.1-2025-11-13 across all three backbone settings, consistent with the CL-bench evaluation protocol[[12](https://arxiv.org/html/2604.27660#bib.bib450 "CL-Bench: a benchmark for context learning")]. The Generator (Figures[11](https://arxiv.org/html/2604.27660#A3.F11 "Figure 11 ‣ Appendix C Case Study ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?") and[13](https://arxiv.org/html/2604.27660#A3.F13 "Figure 13 ‣ Appendix C Case Study ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?")) implements each proposal into a concrete SKILL.md. Algorithm 1 Ctx2Skill: Self-Evolving Context-to-Skill Framework

Require: Context C, Iterations N, Tasks per iteration M, LM policies \pi
Ensure: Final evolved Reasoner skill set \mathcal{S}_{*}^{R}
1:\mathcal{S}_{0}^{R},\mathcal{S}_{0}^{C},\mathcal{Q}^{h},\mathcal{Q}^{e}\leftarrow\emptyset\triangleright Initialize skill sets and probe sets
2:for i\leftarrow 1 to N do
3:// — Task Generation, Reasoning, and Judging —
4:\{(t_{m},\mathcal{R}_{m})\}_{m=1}^{M}\sim\pi_{\text{Challenger}}(\cdot\mid C,\mathcal{S}_{i-1}^{C})\triangleright Generate tasks and rubrics
5:for m\leftarrow 1 to M do
6:a_{m}\sim\pi_{\text{Reasoner}}(\cdot\mid C,\mathcal{S}_{i-1}^{R},t_{m})\triangleright Reasoner solves task
7:y_{m}\leftarrow\prod_{k}\mathbb{I}[r_{m,k}(a_{m})=\text{pass}]\triangleright Judge evaluates rubrics
8:end for
6:// — Routing & Skill Co-evolution —
7:\mathcal{F}_{i}\leftarrow\{m:y_{m}=0\},\quad\mathcal{P}_{i}\leftarrow\{m:y_{m}=1\}\triangleright Route failed and passed tasks
8:\mathcal{S}_{i}^{R}\sim\pi_{\text{Generator}}^{R}\Big(\cdot\mid\pi_{\text{Proposer}}^{R}(\mathcal{F}_{i},\mathcal{S}_{i-1}^{R}),\mathcal{S}_{i-1}^{R}\Big)\triangleright Reasoner diagnoses & updates
9:\mathcal{S}_{i}^{C}\sim\pi_{\text{Generator}}^{C}\Big(\cdot\mid\pi_{\text{Proposer}}^{C}(\mathcal{P}_{i},\mathcal{S}_{i-1}^{C}),\mathcal{S}_{i-1}^{C}\Big)\triangleright Challenger diagnoses & updates
10:// — Probe Set Accumulation —
11:if\mathcal{F}_{i}\neq\emptyset then\mathcal{Q}^{h}\leftarrow\mathcal{Q}^{h}\cup\{\arg\min_{m\in\mathcal{F}_{i}}(\text{rubric pass rate})\}\triangleright Add hardest failure
12:if\mathcal{P}_{i}\neq\emptyset then\mathcal{Q}^{e}\leftarrow\mathcal{Q}^{e}\cup\{\arg\min_{m\in\mathcal{P}_{i}}(\text{number of rubrics})\}\triangleright Add easiest success
13:end for
14:// — Cross-Time Replay Selection —
15:for i\leftarrow 1 to N do
16:\rho^{h}(i)\leftarrow\frac{\sum_{q\in\mathcal{Q}^{h}}y_{q}(\pi^{R};C,\mathcal{S}_{i}^{R})+1}{|\mathcal{Q}^{h}|+1}\triangleright Smoothed hard pass rate
17:\rho^{e}(i)\leftarrow\frac{\sum_{q\in\mathcal{Q}^{e}}y_{q}(\pi^{R};C,\mathcal{S}_{i}^{R})+1}{|\mathcal{Q}^{e}|+1}\triangleright Smoothed easy pass rate
18:end for
19:i^{*}\leftarrow\arg\max_{i}\left(\rho^{h}(i)\cdot\rho^{e}(i)\right)\triangleright Select best balance
20:return\mathcal{S}_{i^{*}}^{R}

Algorithm. Algorithm[1](https://arxiv.org/html/2604.27660#alg1 "Alg. 1 ‣ Appendix B Implementation Details ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?") summarizes the complete Ctx2Skill pipeline. Given a context C, the framework runs N self-play iterations (lines 2–13). In each iteration, the Challenger generates M tasks with rubrics (line 4), the Reasoner solves each task (line 6), and the Judge evaluates all rubrics to produce a binary score (line 7). The outcomes are then routed: failed tasks are sent to the Reasoner Proposer–Generator pair, and passed tasks to the Challenger Proposer–Generator pair, yielding updated skill sets \mathcal{S}^{\mathrm{R}}_{i} and \mathcal{S}^{\mathrm{C}}_{i} (lines 8–9). Meanwhile, the hardest failure and easiest success from each iteration are accumulated into the probe sets \mathcal{Q}^{\mathrm{h}} and \mathcal{Q}^{\mathrm{e}} (lines 11–12). After all iterations, Cross-Time Replay re-evaluates every \mathcal{S}^{\mathrm{R}}_{i} on both probe sets and selects the iteration i^{*} that maximizes \rho^{\mathrm{h}}(i)\cdot\rho^{\mathrm{e}}(i) (lines 15–19), returning \mathcal{S}^{\mathrm{R}}_{i^{*}} as the final skill set (line 20).

Limitations and Future Work. Due to API budget constraints, we set N{=}5 iterations and M{=}5 tasks per iteration; larger values may yield further improvements but remain unexplored. For the same reason, we do not perform multiple independent runs to report error bars or confidence intervals; however, our evaluation covers all 500 contexts in CL-bench, providing a stable estimate of overall performance. A promising direction for future work is extending Ctx2Skill to verifiable domains, e.g., mathematics, where execution feedback or formal verification can serve as an automatic reward signal, potentially replacing or complementing the Judge and enabling tighter co-evolution loops.

## Appendix C Case Study

In this section, we conduct a detailed case study for diverse tasks from CL-bench to visually show the advantages of Ctx2Skill. For ease of reading and comprehension, we embed the analysis and discussion of each case directly within the corresponding figure. Due to the length of some contexts and responses, we omit portions that are not directly relevant to the rubric evaluation to improve readability. We present one representative case from each of the four CL-bench categories, namely _Domain Knowledge Reasoning_ (Figure [5](https://arxiv.org/html/2604.27660#A3.F5 "Figure 5 ‣ Appendix C Case Study ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?")), _Rule System Application_ (Figure [6](https://arxiv.org/html/2604.27660#A3.F6 "Figure 6 ‣ Appendix C Case Study ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?")), _Procedural Task Execution_ (Figure [7](https://arxiv.org/html/2604.27660#A3.F7 "Figure 7 ‣ Appendix C Case Study ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?")), and _Empirical Discovery & Simulation_ (Figure [8](https://arxiv.org/html/2604.27660#A3.F8 "Figure 8 ‣ Appendix C Case Study ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?")), comparing GPT-4.1 responses generated with Ctx2Skill skills against those generated without any skills. Across all four cases, a consistent pattern emerges: the response with Ctx2Skill skills demonstrates more structured reasoning, stricter adherence to rubric requirements, and better compliance with system prompt constraints, whereas the response without skills tends to miss fine-grained requirements such as output format specifications, numerical constraints, or behavioral rules embedded in the system prompt. These qualitative observations complement the quantitative results in Section[4](https://arxiv.org/html/2604.27660#S4 "4 Experiments ‣ From Context to Skills: Can Language Models Learn from Context Skillfully?") and confirm that the skills discovered by Ctx2Skill encode actionable procedural knowledge that directly guides the Reasoner toward more complete and rubric-compliant responses.
